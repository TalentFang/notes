```bash

# 注意：3.x 使用 ./Configure（大写C），不再支持 ./config
```

**修改难度：高**

#### 文件 1：`roles/redis/vars/main.yml`
```yaml

soft_dir: /data/asap/MAXS-CT/valkey-{{ valkey_version }}
```

#### 文件 2：`roles/redis/tasks/main.yml`
- 所有 `redis-maxs-ct` → `valkey-{{ valkey_version }}`
- 所有 `redis-server` → `valkey-server`（二进制名称）
- 所有 `redis-cli` → `valkey-cli`

#### 文件 3：`roles/redis/templates/redis.conf.j2`
- Valkey 8.1 兼容 Redis 7.2 配置格式
- 新增参数：`enable-debug-command no`（安全加固）
- `ssa_path` 路径更新

#### 文件 4：`roles/redis/templates/redis_single.conf.j2`
同上。

#### 文件 5：`roles/redis/templates/sentinel.conf.j2`
- Sentinel 配置与 Valkey 兼容，路径更新即可

#### 文件 6：`roles/redis/templates/asap_redis.service.j2`
- `ExecStart` 路径更新为 valkey-server
- `ExecStop` 路径更新为 valkey-cli

#### 文件 7：`roles/transfer-redis/tasks/main.yml`
- tar 包名更新为 `valkey-{{ valkey_version }}-linux-{{ arch }}.tar.gz`

#### 关键注意事项
- 密码 `!QAZxsw2#EDC(0Ol1)` 保持不变（硬编码在 4 个模板中）
- 端口 16379 保持不变
- 数据为缓存，升级重启后自动重建，不涉及数据迁移

- 从 docker 二进制包中提取 containerd

- 配置 registry mirror
- 配置 CRI socket：`unix:///run/containerd/containerd.sock`

```toml

  [plugins."io.containerd.grpc.v1.cri".containerd]

      runtime_type = "io.containerd.runc.v2"
      [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options]
        SystemdCgroup = true
  [plugins."io.containerd.grpc.v1.cri".registry]
    [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
      [plugins."io.containerd.grpc.v1.cri".registry.mirrors."{{ registry }}:5001"]
```

## 五、回滚策略

| 组件 | 回滚方式 | 回滚窗口 |
|------|----------|----------|
| JDK | 恢复旧 `JAVA_HOME` 路径，alternatives 切换回 JDK 8 | 10 分钟 |
| OpenSSL | 保留旧版 `/usr/local/openssl-1.1.1q` 目录，修改 symlink | 10 分钟 |
| OpenSSH | RPM 降级：`rpm -Uvh --oldpackage openssh-9.8p1*.rpm` | 15 分钟 |
| Docker | 停止 containerd，恢复旧 Docker 二进制，启动 dockerd | 30 分钟 |
| K8s | etcd 快照恢复：`kubeadm reset` + 重新部署旧版 1.23.0 | 2 小时 |
| etcd | 快照恢复：`etcdctl snapshot restore` | 30 分钟 |
| Kafka | 切换业务 bootstrap.servers 回旧集群（旧集群需保留可用） | 15 分钟 |
| Valkey | 数据为缓存，回退 Redis 二进制即可 | 10 分钟 |
| Registry | 替换回旧版 binary + 旧 config.yml | 5 分钟 |
| Prometheus | 旧监控数据可丢弃，回退二进制即可 | 10 分钟 |
| Exporters | 替换旧二进制 | 5 分钟 |
| KeepAlived | RPM 降级 | 5 分钟 |

## 六、关键风险

| 风险 | 等级 | 建议 |
|------|------|------|
| Docker→containerd 存储架构不兼容 | **严重** | 保留 `/var/lib/docker` 目录，提前准备镜像导入方案 |
| K8s 1.23→1.36 跨 13 个大版本 | **严重** | 保留 etcd 快照，建议先重建集群 |
| Kafka ZK→KRaft 不可逆 | **高** | 新集群并行运行，消费完旧数据后再下线旧集群 |
| JDK 8→21 模块化/API 变更 | **高** | 业务代码需在测试环境充分验证 JVM 参数兼容性 |
| Prometheus TSDB 格式不兼容 | **中** | 丢弃旧数据，重新采集（监控数据可重建） |
| OpenSSL 3.x 密码套件变更 | **中** | 保留旧版 openssl 库路径，出问题时切换 |
| KeepAlived 内核要求 4.18+ | **中** | 先检查所有节点内核版本 |
