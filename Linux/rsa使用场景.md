## 1.关键单向特性

1. **私钥可以算出公钥**
    私钥内自带 、，e 是标准固定值，只需提取 n 就能拼接出完整公钥；
    Linux 命令验证：`ssh-keygen -y -f id_rsa` 从私钥直接导出公钥。
2. **公钥无法反推私钥**
    仅拿到 (e,n)，要算出 d 必须对 n 做大数质因数分解；上千位大整数分解在现有计算机下几乎不可能，这是 RSA 安全根基。

## 2.加密 / 签名配对规则（最容易混淆）

### 规则 1：公钥加密 → 私钥解密（加密传输场景）

1. 对方拿**你的公钥**加密明文；
2. 只有你手里的**私钥**能解开密文；
    
    用途：传输隐私数据，防止窃听。

### 规则 2：私钥签名 → 公钥验签（SSH 登录场景）

1. 你用**私钥**对一段消息生成数字签名；
2. 任何人用你的**公钥**验证签名是否合法；
    
    用途：证明 “消息一定是私钥持有者发出”，防伪造、抵赖。

> SSH 免密登录用的就是这套签名逻辑，不是加密。

## 3. 文件层面关系（SSH 密钥文件举例）

1. `id_rsa`（私钥文件）
    
    包含完整机密参数 、、、，文件必须严格保密，权限 600，泄露则整个密钥体系作废。
2. `id_rsa.pub`（公钥文件）
    
    只存 (e,n)，可随意分发；服务器 `authorized_keys` 里存的就是这串内容。

## 使用场景
### 场景一：RSA 用于“加密数据”（现实中使用极少）

假设你要给 etcd 服务器发一个极短的密码（比如 `123456`）。

-   **持有者**：etcd 服务器持有 **私钥（钥匙）**，并把 **公钥（锁）** 公开给了你。
-   **你的操作（发送方）**：你用这把**公钥（锁）** 把明文 `123456` 锁进一个箱子里（`密文 = 公钥(明文)`）。
-   **传输过程**：黑客截获了箱子，但由于没有私钥（钥匙），他打不开。
-   **服务器操作（接收方）**：服务器收到箱子后，用自己的**私钥（钥匙）** 打开箱子（`明文 = 私钥(密文)`），读取 `123456`。

**致命缺陷**：
由于数学算法的限制，RSA能加密的数据长度**不能超过密钥长度（通常是2048位，即256个字节）**。你想发一个1KB的HTTP请求？RSA根本装不下。所以，**RSA几乎从不直接用来加密业务数据。**

---

### 场景二：RSA 用于“数字签名”（最核心用途）

这是你在 `.crt` 证书和 etcd 认证中**真正遇到**的场景。这里不加密数据，而是**证明“这东西是我发的”**。

-   **持有者（发送方）**：持有 **私钥**。他用私钥给文件（如 `etcd.conf`）生成一个“指纹”（签名：`签名 = 私钥(文件哈希值)`）。
-   **你的操作（接收方）**：你持有CA给的 **公钥**。你收到文件和签名后，做两件事：
    1.  你自己算一遍文件的哈希值（`H1`）。
    2.  你用公钥解开签名，得到里面的哈希值（`H2`）。
-   **验证**：如果 `H1 == H2`，证明：**这个文件在传输中没被篡改（完整性），并且确实是私钥持有者发的（身份验证）**。

> **这就是 `.crt` 证书的运作核心！** CA机构用私钥给你的公钥签名，你的浏览器用CA的公钥去验证这个签名，确认这个证书是合法的。

---

### 场景三：RSA 真正扛大梁的地方 —— “混合加密”（HTTPS 就是这样干的）

既然 RSA 加解密慢（比对称加密慢1000倍）且只能加密短文本，那 HTTPS 是怎么加密整个网页的呢？答案是 **RSA + 对称加密 混合双打**。

1.  **第一步（握手阶段 - 用 RSA）**：
    -   浏览器拿到服务器的 **公钥（锁）**。
    -   浏览器随机生成一个对称加密密钥（比如 AES 算法的密钥，称之为 `会话密钥`）。
    -   浏览器用服务器的 **RSA公钥** 把这个 `会话密钥` 加密，传给服务器。
2.  **第二步（数据传输阶段 - 用对称加密）**：
    -   服务器用 **RSA私钥** 解开，得到 `会话密钥`。
    -   **从此以后，所有HTTP报文（Header和Body）都用这个 `会话密钥` 进行加密传输**。

> **经典结论**：**RSA 只负责传递“钥匙”，不负责“锁门”。** 开门后的所有通信，交给了速度极快的 AES 等对称加密算法。

---

### 总结：RSA 通信流程图

```text
[发送方]                                    [接收方]
   |                                            |
   | 1. 持有接收方的公钥 (锁)                    | 持有私钥 (钥匙)
   |                                            |
   | 2. 生成临时的“对称密钥” (比如: ABC123)     |
   | 3. 用公钥加密这个密钥:                       |
   |    Encrypted_Key = RSA(公钥, "ABC123")      |
   |-------------------------------------------->|
   | 4. 传输 Encrypted_Key                        |
   |                                            | 5. 用私钥解密:
   |                                            |    "ABC123" = RSA(私钥, Encrypted_Key)
   |                                            |
   | 6. 用 "ABC123" 加密真正的业务数据 (HTTP)   |
   |    Cipher = AES("ABC123", "GET /...")       |
   |-------------------------------------------->|
   |                                            | 7. 用 "ABC123" 解密:
   |                                            |    "GET /..." = AES("ABC123", Cipher)
```
